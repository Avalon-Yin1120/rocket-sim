================================================================================
                     三级火箭 / 探月模拟器 · 技术文档
================================================================================

> 这是技术文档（原 README 全文）：物理模型与公式、制导判据、参数含义、调参步骤。
> 想先跑起来看效果，请回 [项目说明](../README.md)；想看重构过程中踩过的坑，
> 见 [重构复盘](REVIEW.md)。

一个用 Python + Pygame 写的三级火箭发射 / 探月模拟器。目标是"尽可能真实地"
演示现代运载火箭从点火、重力转弯、级间分离到入轨或坠毁的全过程，以及地月转移
与近月制动。物理模型包含变质量推力、随高度变化的重力、指数大气、气动阻力与
气动力矩、TVC/RCS 姿态控制、月球引力与双主天体切换等。
（pymunk 只被当成位置/速度容器使用，从未接入它的求解器，不构成实际依赖；
地球自转**没有**被真正模拟，详见第 12、13 节。）


================================================================================
0. 本次修订（v11.1）：行为变化摘要
================================================================================

先读这一段——第 1、2、4 条会直接改变你看到的飞行过程。

修复：
  1. 发动机改为"锁存主阀"。点火之后不需要按住任何键；W 键改为切换点火/关机。
     旧版本在默认（手动）模式下，T-0 点火后会被"没按 W 就关机"的检查立刻关掉，
     火箭根本不会起飞。
  2. 着陆即关机。触地（径向速度 < 30 m/s）会关掉发动机并锁死，不再出现
     "坐在发射台上继续烧燃料 → 抛级 → 下一级从台上再次起飞"；landed_soft
     也纳入"飞行结束"条件，自动学习会记录这次结果。
  3. 质心模型方向修正。载荷舱/整流罩现在算在箭体最顶端，与渲染一致。
     旧实现把载荷放在本地原点附近再往上叠分级，等价于"整流罩长在屁股上"。
  4. 入轨判据抬高到近地点 ≥ 180 km，并加入滞回（掉出用 150 km）。
     旧判据（近地点 > 100 km）会把近地点贴着 100 km 的"擦大气"轨迹判成已入轨——
     仓库自带的 flight_learn.json 里 11 次"成功"大多如此。现在这类轨迹显示
     "亚轨道（近地点过低）"，会自动学习也终于能拿到失败样本。
  5. 末级制导重写。不再用"燃料剩 40% 且 vy>400 就关机 / vy<80 再点火"这种硬编码
     垂直速度阈值，改为判据驱动：抬远地点 → 滑行 → 远地点圆化。当前阶段显示在
     HUD 的"末级阶段"一行（动力上升/滑行/圆化/已关机）。
  6. 风场时变项从 9 秒周期改为约 94 分钟（真实风切变不是秒级现象）；碎片改为
     按各自高度取风。
  7. 再入热流衰减改为按物理时间（旧实现每帧 ×0.9，倍速越高衰减越快）。
  8. 相机与高度表量程改用物理时间推进；手动模式锁定缩放，不再随高度漂移；
     缩放下限放宽到 1e-5 px/m，缩到底可以看到完整地球圆盘（以前 disk 模式
     几乎不可达）。高度表量程的平滑移入 Camera，main 不再伸私有字段。
  9. 配置加载增加校验：缺字段 / 非正数会打印明确级号与原因再回退到内置参数；
     DEFAULT_CONFIG_TEXT 现在由 DEFAULT_STAGES 生成，两者不会再各自漂移。
 10. 配置加载增加校验：缺字段 / 非正数会打印明确级号与原因再回退到内置参数；
     DEFAULT_CONFIG_TEXT 现在由 DEFAULT_STAGES 生成，两者不会再各自漂移。
 11. 清理：解体时载荷舱也会生成碎片；移除 view_mode / draw_atmosphere /
     screen_top_alt / screen_bot_alt 等死代码。
 12. **参考系自洽性（最重要的一条）**：轨道根数不再叠加"发射场自转线速度"。
     把一个速度偏置逐帧贴到已经在另一个参考系里积好的轨迹上，得到的不是任何一条
     真实轨道——偏置会贡献 c·v 这一项，而 v 的方向沿轨迹一直在转，于是"轨道"在
     发动机完全关机时自己漂移。实测纯滑行 220 s，近地点从 -20 km 漂到 +180 km，
     最后被判成"已入轨"。现在轨道根数与轨迹严格自洽（tools/orbit_check.py 可验证，
     能量相对漂移约 1e-14）。代价是地球自转借力（约 438 m/s）不再计入，入轨速度
     要求比现实"贵"这么多；默认火箭仍然入得了轨：实测 T+440 s 入轨，
     近地点 181 km / 远地点 1179 km，之后轨道稳定不变。

新增（原先完全没有验证手段）：
  · tools/orbit_check.py   轨道守恒自检：圆轨道跑一段，根数必须守恒
  · tools/flight_test.py   无头飞行 + 遥测输出，可做参数扫描与回归对比
  · tools/moon_orbit_check.py  绕月捕获自检：直接构造月球交会，验证近月制动

0b. v11.2：月球与多套火箭预设
================================================================================

新增能力：

  1. **月球**。月球按地心匀速圆周运动给出位置（二维模型只能这样，倾角/偏心率
     都没有表示），引力按平方反比算，参与平动积分、轨道预测和渲染。
     仿真里现在有两个主天体：月心距小于月球影响球（66,200 km）就把月球当主天体，
     HUD、轨道根数、环绕速度、高度表全部跟着切换。
  2. **绕月运行**。制导链：入地球停泊轨道 → 等相位 → TLI（地月转移入射）→
     滑行约 5 天 → 近月制动捕获 → 圆化。实测（tools/flight_test.py --preset lunar）
     最终进入 19,378 × 21,141 km、e=0.04 的绕月轨道；单独测近月点时
     （tools/moon_orbit_check.py --perilune 2000）能打出 164 × 317 km 的近圆轨道。
  3. **四套内置火箭预设**（P 键循环切换）：
        sounding  探空火箭 2 级：够不到入轨速度，演示"入轨失败 → 再入 → 撞地"
        light     轻型三级（原默认）：理想 Δv 11.8 km/s，实测 Max-Q 59 kPa
        medium    中型三级：起飞推重比 1.42、结构系数 8/12/19%，理想 Δv 11.0 km/s，
                  实测 Max-Q 27 kPa（真实火箭 30~35）→ 入 233 × 549 km 轨道
        lunar     重型四级探月：理想 Δv 14.7 km/s，其中前三级的 10.1 km/s 进停泊
                  轨道、转移级的 4.5 km/s 留给 TLI 和近月制动
     `rocket_config.json` 里用 "preset" 选预设，其余字段（mission / payload /
     payload_len / payload_radius / pitch_v_ref）可以覆盖预设值；给了 stages
     就以 stages 为准。
  4. **自动学习按预设分开存**。俯仰程序的合适形状取决于推重比，一张全局表会把
     上一枚火箭的经验硬套到新火箭上。flight_learn.json 现在是 v2 格式，
     每个预设各有一份表、代数和历史（旧 v1 文件会自动归入 light 预设）。

这一轮踩到的坑（都留在代码注释里，值得一读）：

  · 把自转速度**逐帧**贴到地面系轨迹上算轨道 → 纯滑行 220 s 近地点自己漂 200 km，
    旧版所有"擦大气式入轨"都建立在这个漂移上（见 5.5）。
  · 圆化 burn 用上升段俯仰程序指方向 → 下降段时推力偏离速度方向 40°，
    近地点越烧越低（130 km → 2 km）。
  · 变轨用"顺着速度"而不是"切向" → 径向分量只抬高远地点，近地点不动。
  · 近月点预测里把双曲线的 a 设成 inf → 双曲线开普勒方程算出无穷大的"到近月点
    时间"，近月制动**永远不点火**（这是最隐蔽的一个，端到端表现为"每次都飞过月球"）。
  · 预测积分的步长只看"离月球多远" → 近地轨道上用了 600 s 步长（周期的 1/10），
    RK4 把轨道积飞，预测出假的近月交会。
  · TLI 相位判据的过零点检测把 ±π 回绕也算成了过零 → 相位差 137°，火箭飞到月球
    轨道另一侧（最近月距还有 37 万公里）。

尚未处理（详见末尾"已知限制"）：
  · 默认火箭起飞推重比 3.3（真实 1.3~1.6），实测 Max-Q 59 kPa（真实 30~35）；
  · Isp 只用真空值，不随环境气压变化；
  · 1×–100× 仍走 20 步显式欧拉而不是 RK4（两条路径精度都够，RK4 主要是更快）；
  · "自动学习"仍是整张俯仰表乘一个标量的伪学习（奖励没有参与更新）；
  · 地球自转没有被真正模拟（见第 12 条与 13. 已知限制）；
  · 近月点预测仍与实际有偏差（见 13. 已知限制），所以月球任务瞄准的是
    15,000 km 的远距交会，靠近月制动把轨道收圆。

1. 快速开始
================================================================================

依赖安装：

    pip install -r requirements.txt

只有两个第三方包：pygame-ce 与 pymunk，其余 import 都是标准库。
已装原版 pygame 的话，把 requirements.txt 里那行换成 pygame>=2.1（两个包提供同一个
pygame 模块，不要同时安装）。Python 3.9 以上，开发与验证环境是 3.13.1。

运行：

    python main.py

首次运行会在同目录生成 rocket_config.json（带中文注释），后续所有火箭参数都从
这里读。JSON 写坏时程序会打印出错级号与具体原因，再回退到 config.py 里的
DEFAULT_STAGES；HUD 事件区的第一行会写明本次实际生效的参数来源。

最短上手路径：

  1. 运行程序，屏幕中央显示 T-10 倒计时，左上角事件区显示"参数来源：..."。
  2. 倒计时结束，一级自动点火并直接起飞——不需要按任何键。
  3. 按 Ctrl 切到自动模式，火箭按俯仰程序做重力转弯（手动模式也能飞，
     只是姿态要用 A/D 自己保持）。
  4. 观察右侧高度表与左上角遥测：速度、攻角、动压、"末级阶段"。
  5. 三级工作结束时 HUD 显示"✓ 已入轨"或"亚轨道（近地点过低）"。
     按 ↑ 加到 100× 倍速，几十秒就能看完一次入轨。

2. 操作说明
================================================================================

  按键            功能
  ------------    ------------------------------------------------------------
  A / D           手动控制姿态（动力段 = TVC 摆管；滑行段 = RCS 侧喷）
  W               切换发动机主阀：一次按键点火，再按一次关机
  Ctrl            切换自动/手动姿态控制
  M               切换相机自动/手动模式
  T               显示/隐藏 HUD
  P               换下一枚火箭（循环内置预设：探空 / 轻型 / 中型 / 探月）
  ↑ / ↓           时间倍速 ±1 档：
                  1× → 2× → 5× → 10× → 50× → 100× → 500× → 1000× →
                  2000× → 5000× → 10000×
  鼠标滚轮        缩放（自动切到手动相机模式；手动模式下缩放不再随高度变化）
  R               重新发射（保留自动学习进度）
  ESC             退出

注意：W 是"主阀锁存"，不是"按住才有推力"。点火后松开按键发动机继续工作；
想做一次滑行就再按一次 W 关机。

倍速受积分预算限制：推力段每块 ≤0.05 s、滑行段每块 ≤0.5 s、每帧最多 400 块。
所以推力段的实际倍速最高约 1200×、滑行段约 12000×；按到更高档时 HUD 会显示
"时倍 ×10000 → 实际 ×1200（步长预算）"。地月转移约 5 天，用 10000× 看约 40 秒。

================================================================================
4. 每个文件做什么
================================================================================

--------------------------------------------------------------------------------
main.py — 主循环
--------------------------------------------------------------------------------

程序入口。每一帧做这几件事：

  1. 读事件：键盘、鼠标滚轮。
  2. 物理推进：把整帧时间切成 ≤50 ms 的小块，逐块调用 rocket.update。
     这是为了保证 100x 倍速下姿态控制律的采样周期仍然足够细。
  3. 相机更新：跟随火箭位置和高度，按模式（自动/手动）调整缩放。
  4. 渲染：按固定顺序调用 rendering 包的各函数。
  5. HUD 渲染：高度表、左上角遥测面板、倒计时、相机模式提示、底部操作提示。

为什么物理要分块：
  自动控制律每帧只算一次。100x 倍速时一帧推进 1.67 秒物理时间，控制周期
  1.67 秒，姿态系统相位滞后接近 180°，必然震荡。切成 ≤50 ms 的小块后，
  100x 时一帧调用约 34 次 rocket.update，控制周期稳定在 50 ms，姿态稳定。

--------------------------------------------------------------------------------
config.py — 全局常量
--------------------------------------------------------------------------------

分几类：

  · 物理常量：G0（海平面重力）、R_EARTH（地球半径）、RHO0（海平面大气密度）、
    H_SCALE（大气标高）。
  · 载荷舱：PAYLOAD（质量）、PAYLOAD_LEN / PAYLOAD_RADIUS / PAYLOAD_CD。
    它是质量模型里最顶端的独立一段，与分级参数分开。
  · 发射场：LAUNCH_LAT_DEG（纬度）、EARTH_OMEGA（自转角速度）、
    COUNTDOWN_SECONDS（倒计时长度）。
  · 控制参数：TVC 摆角限幅、作动器延迟、RCS 推力。
  · 失败阈值：CRASH_SPEED / BREAK_Q / BREAK_AOA / BURNUP_HEAT。
  · 入轨判据：ORBIT_MIN_PERIGEE_ALT（180 km，判定入轨）与
    ORBIT_EXIT_PERIGEE_ALT（150 km，掉出轨道）。两者不同即构成滞回，
    避免状态在阈值附近反复横跳。
  · 配置加载：load_stages() 从 rocket_config.json 读参数，支持 // 与 /* */ 注释
    （由 _strip_json_comments 剔除），并用 _normalize_stages() 校验。

自动学习用的俯仰表在 physics/autolearn.py，不在这里。

参数校验与回退：

  load_stages() 逐级检查缺字段、非数值、非正数，出错时打印级号与原因，然后回退到
  DEFAULT_STAGES。实际生效的来源记录在 config.CONFIG_SOURCE，启动时会写进 HUD
  事件区第一行——"改了 json 却没生效"因此一眼可见。

开关 USE_JSON_CONFIG：

  True（默认）：优先读 JSON；文件不存在则生成一份默认文件。
  False       ：忽略 JSON，直接用代码里的 DEFAULT_STAGES。

DEFAULT_CONFIG_TEXT 由 DEFAULT_STAGES 渲染生成（带字段注释），所以不存在
"两份默认参数不一致"的问题。

--------------------------------------------------------------------------------
physics/ — 物理模型
--------------------------------------------------------------------------------

拆成 5 个模块：

  rocket.py    Rocket 主类：动力学、姿态、级间逻辑、控制律、末级制导、
               轨道计算、失败模式。
  stage.py     Stage：单级参数与状态（干重、燃料、推力、比冲、几何尺寸、
               阻力系数），提供 mass 与 fuel_frac。
  particle.py  Particle（世界坐标，爆炸/火光）与 LocalParticle（相对箭体的
               本地坐标，尾气——这样粒子永远贴着喷管，不受火箭速度影响）。
  debris.py    Debris：分离级与解体碎片，独立积分，受重力和阻力，落地后静止。
  autolearn.py FlightLearner：跨次发射累积的"速度 → 目标俯仰角"查找表，
               存在 flight_learn.json。

--------------------------------------------------------------------------------
camera.py — 相机
--------------------------------------------------------------------------------

  · Camera 类保存相机位置、缩放、模式，并负责高度表量程上限的平滑
    （update_altitude_span / alt_max 属性）。
  · 自动模式：目标缩放由高度决定（对数插值），0 m → 40 px/m，
    200 km → 0.05 px/m，1000 km → 0.001 px/m。
  · 手动模式：缩放是**绝对值** manual_scale，只由滚轮改变，不随高度漂移。
    从自动切到手动时直接沿用当前 scale，所以切换瞬间是无缝的。
    范围 [1e-5, CAM_MAX_SCALE]：缩到 1e-5 px/m 时地球半径只剩约 64 px，
    可以看全整个地球（也就是进入了 earth.py 的圆盘模式）。
  · 缩放上限 CAM_MAX_SCALE = 150（px/m），防止火箭放大到屏幕上占几万像素
    导致渲染慢。
  · 相机位置每帧直接赋值给火箭位置（无插值），保证火箭在屏幕上固定于纵向
    55% 处，无论多快都不抖动。缩放与量程的平滑按**物理时间**推进：
    旧实现用帧时间，100× 倍速下火箭在 0.3 秒真实时间里爬升几十公里，
    镜头和量程完全跟不上。

================================================================================
5. 物理模型
================================================================================

--------------------------------------------------------------------------------
5.1 参考系
--------------------------------------------------------------------------------

世界坐标系是地心平面近似：

  · 原点在发射点地面。
  · x 向东，y 向上。
  · 地心位于 (0, -R_EARTH)。

高度用径向距离算：

  r_center = hypot(x, y + R_EARTH)
  altitude = r_center - R_EARTH

不是简单的 y。这样才能正确模拟地球曲率——火箭飞到很远处时，真实海拔由
径向距离决定。

--------------------------------------------------------------------------------
5.2 平动动力学
--------------------------------------------------------------------------------

每帧（子步）对火箭刚体施加合力和力矩：

推力
  F_thrust = mdot × ve × throttle
  mdot = thrust / (isp × G0)
  推力方向 = 姿态角 theta + TVC 摆角 delta + 固定偏置 tvc_bias。
  燃料按 mdot × h 消耗，烧完后触发分离。

重力
  g(r) = G0 × (R_EARTH / r)^2
  方向指向地心：(−rx/r, −ry/r)

空气阻力
  rho(h) = RHO0 × exp(-h / H_SCALE)     # 指数大气
  F_drag = 0.5 × rho × cd × A × v^2
  速度是相对风的（风廓线 wind_speed(alt) 模拟低空切变 + 高空急流）。

最大动压节流
  q = 0.5 × rho × v^2
  if q > 30 kPa:
      throttle = max(0.7, 1 - (q - 30000) / 150000)
  模拟真实火箭在 Max-Q 段降低推力，减轻结构载荷。

--------------------------------------------------------------------------------
5.3 姿态动力学
--------------------------------------------------------------------------------

姿态角 theta、角速度 omega 通过力矩积分：

  I × domega/dt = tau
  omega += tau/I × dt
  theta += omega × dt

力矩来源：

  1. TVC 控制力矩：tau = F_thrust × L_engine × sin(delta)，
     其中 L_engine 是发动机到质心的距离。
  2. RCS 控制力矩（发动机关机后）：tau = F_rcs × r_arm，
     r_arm 是喷口到质心的力臂。
  3. 气动恢复力矩：tau = q × A × CN × arm，CN = 2 sin(aoa) 随攻角饱和。
     模拟"飞镖式"回正。
  4. 气动阻尼力矩：tau -= C_damp × q × A × L^2 × omega / v，抑制摆振。

质心和转动惯量每帧重算：把载荷舱和每一存活级当作均匀圆柱，用平行轴定理叠加。
本地坐标原点在当前最下面一级的底部（喷管出口），+y 指向箭体头部，载荷舱在整叠
结构的最顶端——与 rendering/rocket.py 的绘制顺序一致。烧油、抛级都会改变质心
位置，从而改变力臂和 I。

--------------------------------------------------------------------------------
5.4 级间分离
--------------------------------------------------------------------------------

分离时两级动量守恒：

  dv_debris = -v_rel × m_after / m_total
  dv_rocket = +v_rel × m_before / m_total

v_rel = 2.5 m/s 模拟弹簧/火药推冲器。碎片作为独立 Debris 继续飞行，受重力
和阻力作用，落地后静止。

--------------------------------------------------------------------------------
5.5 地球自转借力（未模拟）
--------------------------------------------------------------------------------

点火时会算出真实发射场的自转线速度并写进日志：

  v_rot = EARTH_OMEGA × R_EARTH × cos(LAUNCH_LAT_DEG)

在文昌（19.6°N）约 438 m/s，赤道 465 m/s，普列谢茨克（63°N）只有 211 m/s。

**这个值没有参与仿真。** 理由不是偷懒，而是它在这个模型里无法自洽地表示：

  · 本仿真的世界是"地面静止的惯性系"（没有科氏力，也没有离心力项）。
    既然地面静止，火箭相对地面的速度就是它在惯性系里的速度，轨道根数直接用
    这个速度即可。
  · 早期版本在算轨道时把 v_rot 按当地东向切向叠加到速度上。这一步在数学上是错的：
    把一个速度偏置**逐帧**贴到一条已经在另一个参考系里积出来的轨迹上，得到的不是
    任何一条真实轨道。偏置会给比能量贡献 c·v 一项，而 v 的方向沿轨迹一直在转，
    于是"轨道"在发动机完全关机的情况下自己漂移——实测纯滑行 220 秒，近地点从
    -20 km 漂到 +180 km，然后被判成"已入轨"。

真要把它算进去，只有两条路：把动力学整体搬到转动系并补上科氏力/离心力
（二维切片下需要 ω·sinφ 近似，而且南北向的分量仍然丢失），或者从一开始就在
惯性系里积分并让"地面"真的跟着转。两者都超出当前二维模型的范围，所以这里选择
诚实：不模拟，代价是入轨速度要求比真实发射场"贵"约 438 m/s（大约等于一级多烧
1.5% 的推进剂），并把这件事写进日志和这份文档。默认火箭即使没有这份"免费速度"
也仍然能入轨（见 6.4）。

--------------------------------------------------------------------------------
5.6 轨道根数
--------------------------------------------------------------------------------

每帧用 vis-viva 方程算轨道能量和角动量，速度取 inertial_velocity()，也就是
箭体相对地面的速度（见 5.5，本仿真的世界本身就是惯性系）：

  eps = v^2/2 - mu/r
  h = rx × vy - ry × vx
  e = sqrt(1 + 2 × eps × h^2 / mu^2)
  a = -mu / (2 × eps)
  rp = a × (1 - e)      # 近地点到地心距离
  ra = a × (1 + e)      # 远地点

入轨判据（带滞回）：

  进入：rp 和 ra 都 ≥ R_EARTH + 180 km
  掉出：rp 或 ra < R_EARTH + 150 km

为什么是 180 km 而不是 100 km：100 km 只是卡门线，近地点贴着 100 km 的轨迹会在
几分钟内被阻力吃掉，不是能维持的轨道。仓库自带的 flight_learn.json 里就记录着
11 次这样的"成功飞行"（例如 ra≈8000 km、rp≈100 km），它们全部是靠旧判据
（>100 km）过的线。现在这类轨迹在 HUD 里显示"亚轨道（近地点过低）"。

自检：tools/orbit_check.py 把火箭放进一条已知圆轨道、关掉发动机，验证根数守恒
（实测相对能量漂移约 3e-14，两套积分路径都通过）。滑行段守恒是硬要求——
只要根数在无动力时还在变，画面上的"轨道"就不可信。

HUD 里的速度：

  垂直速度 / 水平速度   相对地面的径向 / 切向分量
  环绕速度              当前高度上圆轨道所需的速度（sqrt(mu/r)），用来一眼看出
                        离入轨还差多少；近/远地点就是用它参与算出来的

--------------------------------------------------------------------------------
5.7 失败模式
--------------------------------------------------------------------------------

  · 撞地爆炸：接触地表时径向速度超过 30 m/s，标记 crashed，生成爆炸粒子。
  · 撞月爆炸：同上，但判据用的是**相对月球**的径向速度（月球本身在动）。
  · 结构解体：动压 > 100 kPa 且攻角 > 30°，标记 broken，每级拆成独立碎片
    飞散。
  · 再入烧毁：热流超过 5 MW/m^2，标记 burned_up。热流用 Sutton-Graves 公式
    k × sqrt(rho/Rn) × v^3 估算。

--------------------------------------------------------------------------------
5.8 月球与双主天体
--------------------------------------------------------------------------------

月球按**地心匀速圆周运动**给出（config.moon_state）：
MOON_DIST = 384,400 km、恒星月 27.321661 天、公转线速度 1023 m/s；
引力按平方反比加进平动积分（substep 与 RK4 两条路径都有），
渲染和物理共用同一个 moon_state(t)，不会两边算错。

**主天体切换**：月心距 < 月球影响球（66,200 km）时主天体是月球，否则是地球。
切换后这些量全部跟着换：

  · 轨道根数（近月点/远月点，判据 rp ≥ 月面 + 50 km）
  · 环绕速度（sqrt(mu_moon/r)）与当地重力
  · 高度表与相机取景参考（focus_alt 变成"距月面高度"）
  · 任务完成判据（绕月轨道 + 近月制动结束）

月球参数：mu = 4.9048695e12 m³/s²、半径 1,737.4 km。二维模型里月球只能在同一个
平面内运动，所以轨道倾角、偏心率、交点进动、太阳摄动都没有表示。

末级制导在探月任务下的完整阶段机（见 6.4）：

  boost → coast → circ → park → tli → transit → loi → done
                        ↑停泊等相位  ↑顺行抬远地点  ↑5 天滑行  ↑近月制动

TLI 的相位判据用开普勒方程算"从当前点飞到转移远地点的时间和角度"，
再和月球届时位置对比，误差过零时点火（精度只取决于积分步长，不靠经验常数）。
TLI 的关机判据用**前向预测的近月点**（_predict_lunar_miss 积分 12 天），
而不是几何远地点——这是把"撞月/擦肩 25 万公里"的随机性压下去的关键。


================================================================================
6. 姿态控制
================================================================================
--------------------------------------------------------------------------------
6.1 手动模式
--------------------------------------------------------------------------------

  · 动力段：左右键直接给 TVC 摆角指令。摆角经一阶延迟（TVC_ACT_TAU = 0.05 s）
    + 速率限制（TVC_RATE_MAX_DEG = 45°/s）后作用到推力方向。
  · 滑行段：左右键给 RCS 归一化指令，转成力矩。

--------------------------------------------------------------------------------
6.2 自动模式
--------------------------------------------------------------------------------

自动模式用 PD 控制跟踪目标姿态：

  err = target - theta
  delta_cmd = Kp × err - Kd × omega          # 动力段：输出 TVC 摆角
  tau_cmd = I × (2.0 × err - 2.5 × omega)    # 滑行段：输出 RCS 力矩

目标姿态来自 physics/autolearn.py 里那张"速度 → 目标俯仰角"查找表
（15 个速度节点，500 ~ 7500 m/s，节点间线性插值）：

  base = table(speed)      # 默认表 = 89.5° × min(1, v / 3500)

速度越大目标姿态越接近水平；3500 m/s 以上一律压到 89.5° 上限。

攻角约束：目标姿态被夹在"当前速度方向 ± max_aoa"范围内。

  if q > 30 kPa:    max_aoa = 8°    # Max-Q 段严控
  elif alt < 30km:  max_aoa = 20°
  else:             max_aoa = 40°   # 高空放宽

--------------------------------------------------------------------------------
6.3 TVC 与 RCS 的区别
--------------------------------------------------------------------------------

  项目          TVC                     RCS
  -----------   ---------------------   ----------------------------
  工作段        发动机点火时            关机滑行段
  力臂          发动机到质心，较短      喷口到质心，较长
  力矩来源      主推力偏斜              侧向小推力
  消耗          不额外消耗工质          消耗 RCS 推进剂

真实现代火箭：第一级和上面级动力段用 TVC，滑行段用 RCS。游动发动机是苏联
传统，本项目没模拟。


--------------------------------------------------------------------------------
6.4 末级制导（判据驱动）
--------------------------------------------------------------------------------

末级由 Rocket._upper_stage_guidance() 控制，共四个阶段：

  boost  动力上升：烧到"远地点 ≥ apogee_target_alt"（入轨任务）/ 预测近月点达标
         （探月任务的 TLI）
  coast  滑行到远地点；圆化 burn 只在**远地点窗口**内点火，越出窗口就熄火等下一圈，
         但近地点低于 130 km（保命线）时无论如何继续烧
  circ   圆化：抬升近地点到 circ_target_perigee_alt，入轨任务还要把远地点-近地点
         之差收到 1500 km 以内
  park   停泊待机（探月）：等 TLI 相位窗口
  tli    地月转移入射：顺行切向烧到"预测近月点 ≤ TLI_PERILUNE_ALT"
  transit 地月转移滑行（约 5 天），进入月球影响球并接近近月点时转 loi
  loi    近月制动：在近月点前半个燃烧时长点火，减速到该高度的环绕速度即停
  done   永久关机

当前阶段显示在 HUD 的"末级阶段"一行（动力上升 / 滑行 / 圆化 / 已关机）。

三个目标值都是 Rocket 的实例属性，初值取自 physics/rocket.py 顶部的常数
（APOGEE_TARGET_ALT = 300 km、CIRC_TARGET_PERIGEE_ALT = 200 km、
CIRC_RELIGHT_VRADIAL = 0），可以按载荷/任务改，也方便做扫描：

  python tools/flight_test.py --apogee 400 --circ-perigee 250

旧实现是"燃料剩 40% 且 vy>400 就关机、vy<80 就再点火"——两个硬编码的垂直速度
阈值，有两个问题：

  · 一改推力/比冲/燃料量（也就是改 rocket_config.json，这个项目的主打功能）
    整段制导就失效；
  · 它会把远地点抬到几千公里才关机，等于把宝贵的 Δv 浪费在抬高远地点上，
    最后近地点只剩 ~100 km，然后被旧判据误判成"已入轨"。

实测（默认配置、默认俯仰表、tools/flight_test.py）：

  T+ 58.9 s  一级分离        T+109.6 s  二级分离
  T+109.6 s  末级关机，远地点 338 km → 滑行 243 s
  T+352.9 s  远地点再点火
  T+439.7 s  已入轨：近地点 181 km / 远地点 1179 km，此后根数不再变化

两个实测出来的经验（已写进代码注释）：

  · 圆化必须在远地点附近点火。把再点火提前到径向速度 +120 m/s（也就是远地点之前）
    最终远地点会从 1179 km 涨到 1755 km——在远地点之外加速等于把能量灌进远地点，
    越烧越扁。
  · 远地点目标不是越高越好：把目标从 300 km 提到 400 km，末级会多烧一段，
    最终远地点反而冲到 2598 km。默认配置在三级点火时的远地点已经有 338 km，
    所以 300 km 这个目标实际上起的是"不要再烧了"的保险作用。

判据驱动版只看轨道根数，与具体火箭参数无关；代价是滑行段明显变长（243 s），
用 100× 倍速看比较合适。

7. 相机
================================================================================

--------------------------------------------------------------------------------
7.1 自动模式
--------------------------------------------------------------------------------

目标缩放按高度对数插值：

  高度        px/m
  --------    --------
  0 m         40
  1 km        ~8
  10 km       ~1
  100 km      ~0.1
  200 km      0.05
  1000 km     0.001

变换平滑，跟随火箭上升逐渐拉远，模拟真实发射直播的镜头。

--------------------------------------------------------------------------------
7.2 手动模式
--------------------------------------------------------------------------------

滚轮直接控制绝对缩放 manual_scale，范围 [1e-5, CAM_MAX_SCALE = 150]。

从自动切到手动时，把当前 scale 直接存为 manual_scale，切换瞬间无缝；之后
**不再随高度变化**——旧实现用另一套高度公式（4/(1+alt/2500)^0.9）反推倍率，
滚轮手感会取决于火箭飞到哪了，既不是这里承诺的行为，也很难用。

缩到 1e-5 px/m 时地球半径只剩约 64 px，可以看到完整地球（圆盘模式）。

--------------------------------------------------------------------------------
7.3 相机位置
--------------------------------------------------------------------------------

  self.x = wx                                            # 直接跟随
  self.y = wy + (0.55 - 0.5) × HEIGHT / self.scale       # 火箭在纵向 55% 处

不加插值。这是为了让火箭在屏幕上位置固定，无论速度多快都不抖动。之前的版本
用 k = 1 - exp(-dt × 12) 插值，高速时会有明显滞后。

8. 渲染管线

--------------------------------------------------------------------------------
8.1 每帧渲染顺序
--------------------------------------------------------------------------------

  draw_sky                 → 黑底
  draw_stars               → 星点（高度淡入）
  draw_earth               → 地球（弧线或圆盘）
  draw_surface_objects     → 地表建筑（只在低空）
  draw_trail               → 历史轨迹
  draw_predicted_orbit     → 引力预测轨道
  draw_debris              → 各碎片
  draw_rocket              → 火箭本体 + 尾焰 + TVC + RCS + 再入辉光
  draw_shock_and_sonicboom → 激波锥、音爆云
  draw_particles           → 尾气 + 爆炸粒子（50x 以上跳过）
  draw_altimeter           → 右侧高度表
  draw_hud                 → 左上角遥测

--------------------------------------------------------------------------------
8.2 地球的两种模式
--------------------------------------------------------------------------------

earth.py 里根据相机缩放选择渲染方式：

  · 圆盘模式（r < 2000 像素）：画完整圆形地球，加大陆、城市灯光、环绕大气、
    昼夜分界。
  · 弧线模式（r >= 2000）：地球太大，用扫描线多边形填充可见地表弧。
    大气层贴着弧线逐列绘制。

注意：自动缩放在 1000 km 高度仍有 0.001 px/m，对应地球半径 6371 像素，
所以**自动播放下永远走弧线模式**。圆盘模式（连同大陆、城市灯光、昼夜分界）
要靠手动相机：按 M 切手动，滚轮缩到 3e-4 px/m 以下即可（下限 1e-5，足够）。

--------------------------------------------------------------------------------
8.3 大气层
--------------------------------------------------------------------------------

弧线模式下的大气层是逐像素渐变，从地表向上依次是浅蓝 → 中蓝 → 深蓝 → 黑。

  · 生成一条 1 像素宽的渐变竖列。
  · 按相机缩放 step 横向拉伸到 step 像素宽（避免竖条纹）。
  · 沿地表弧线逐列 blit。

8.4 性能优化
--------------------------------------------------------------------------------

  · overlay Surface 复用：轨迹、预测轨道、激波线共用几个模块级 Surface，
    每帧先 fill((0,0,0,0)) 再用。
  · 屏幕外剔除：轨迹线、大气层列、地表建筑都做屏幕相交检查。
  · 放大跳过：TRAIL_MAX_SCALE = 8，相机放大超过此值时不画轨迹和预测轨道
    （视野太窄看不到）。
  · 采样步长自适应：地球弧线顶点数随缩放从 1200 降到 150。
  · 粒子渲染关闭：≥50× 时 main.py 直接跳过 draw_particles。
    （注意粒子仍在生成和更新：physics/rocket.py 里的 `dt < 0.3` 判断在
    1×~1000× 下恒成立，所以这里省掉的只是绘制，CPU 照样要花。
    想彻底省掉需要在生成处也判断倍速。）
  · 地形建筑：只在 cam.y < 12000 且 0.05 < cam.scale < 30 时渲染。

9.1 rocket_config.json
--------------------------------------------------------------------------------

字段顺序与中文注释都是自动带的，所以不会再出现"代码里一套、文件里另一套"。

      {
        "name": "第一级",         // 显示名称
        "dry": 550.0,             // 干重 (kg)：结构+发动机+贮箱，不含燃料
        "fuel": 5000.0,           // 燃料质量 (kg)
        "thrust": 280000.0,       // 真空推力 (N)
        "isp": 300.0,             // 比冲 (s)
        "radius": 1.2,            // 箭体半径 (m)，决定气动阻力面积
        "length": 15.0,           // 箭体长度 (m)
        "cd": 0.35                // 阻力系数
      },
      // ... 第二级、第三级
    ]
  }

--------------------------------------------------------------------------------
9.2 参数调整建议
--------------------------------------------------------------------------------

  · 比冲 isp：最有效的调整。液氧煤油 280~310，液氧液氢 380~450。
    提升 10% → Δv 提升约 10%。
  · 干重 dry：越低越好，现代火箭结构质量占比 < 8%。降低干重直接变成有效
    载荷或燃料。
  · 燃料 fuel：增加会同时抬高起飞质量，Δv 增长远小于燃料增长比例。
    优先改比冲和干重。
  · 推力 thrust：一级推重比 1.3~1.6 最佳，太高会增加气动载荷与 Max-Q，
    太低会增加重力损失。
    ⚠ 内置默认参数的一级起飞推重比是 280 kN ÷ (8670 kg × 9.807) = 3.29，
    远高于这个区间——它是早期为了让火箭"必定入轨"而留足余量设的示范值。
    按默认参数跑，动压在 T+10 s 左右就突破 30 kPa 触发 Max-Q 节流，之后长期被
    压在 70% 下限（真实火箭 Max-Q 约 30~35 kPa）。想追求真实感，把一级推力降到
    约 115~130 kN 再重新配平。
  · 半径/长度：影响转动惯量和气动阻力，视觉上也要合理。
  · 阻力系数 cd：圆柱体典型 0.3~0.5，尖端整流罩低至 0.1。

可以先用火箭方程估一下能力（分段递推，m 是该级点火时的总质量）：

  Δv_i = Isp_i × 9.80665 × ln(m_i / (m_i − fuel_i))

默认三级合计约 11.8 km/s，而入轨（含损失、且本仿真不扣自转借力）大约需要
9.7 km/s，所以余量约 2.1 km/s——这也是"自动学习"永远拿到正奖励的原因
（见 13. 已知限制 14）。

改完参数记得对照 physics/rocket.py 顶部的末级制导目标（远地点 300 km、
近地点 200 km）确认还有余量。

--------------------------------------------------------------------------------
9.3 切回代码内置参数
--------------------------------------------------------------------------------

把 config.py 里的 USE_JSON_CONFIG 改成 False，程序会忽略 JSON 直接用
DEFAULT_STAGES。改完不用管 JSON 文件是否存在。


================================================================================
10. 时间加速
================================================================================

TIME_SCALES = [1, 2, 5, 10, 50, 100, 500, 1000]。用 ↑/↓ 逐档切换（共 8 档）。

加速的原理：dt = raw_dt × time_scale，物理时间以 time_scale 倍速推进。

自动控制律的保护：main.py 把整帧切成 ≤50 ms 的小块（500× 以上是 ≤150 ms）。
100× 时一帧约 34 块，每块物理时间 49 ms，控制周期 49 ms，姿态稳定。

注意：500× / 1000× 时块长变成 150 ms，控制周期也跟着变成 150 ms——README 里
"控制周期稳定 50 ms"这个保证在那两档并不成立，姿态可能开始晃。要修需要把控制律
放进子步循环、按固定 50 ms 调用。

粒子的处理：

  · 尾气按**真实时间**累积（每 15 ms 一次），倍速越高粒子数越少，不会爆掉。
  · ≥50× 时只跳过渲染，不跳过生成与更新（见 8.4）。

CPU 开销：100× 时物理耗时明显高于 1×，帧率从 60 降到 15~30。真正的瓶颈是
1×~100× 全走 20 步显式欧拉子步（见 13. 已知限制第 2 条），而不是常数大小。
SUBSTEPS_PER_SEC = 400 与 SUBSTEPS_MAX = 250 都在 physics/rocket.py 里；
注意 SUBSTEPS_MAX 已经封顶在 250，所以"把它从 400 降到 250"没有意义，
要降只能改 SUBSTEPS_MAX 或减小 MAX_CHUNK。


================================================================================
11. 常见问题
================================================================================

Q1：为什么轨道根数在发动机完全关机时还在变？
    参考系没对齐。动力学是在"地面静止的惯性系"里积分的，如果把发射场自转速度
    逐帧叠加到速度上再算轨道，得到的不是任何一条真实轨道（详见 5.5）。
    现在轨道根数直接用箭体速度，滑行段的根数严格守恒；tools/orbit_check.py
    就是为这件事准备的回归自检。

Q2：为什么火箭在轨道上"半空爆炸"？
    碰撞检测用平面 y < 0 判定，而真实地球是球形的。正确做法是用径向距离
    hypot(x, y+R_EARTH) < R_EARTH。

Q3：放大后卡顿？
    三个原因：轨迹线过长、粒子渲染、再入辉光 Surface 过大。
      · 轨迹采样距离 800 m、上限 400 点。
      · 放大超过 TRAIL_MAX_SCALE 时不画轨迹。
      · 再入辉光半径上限 300 px。

Q4：100x 时姿态乱晃？
    main.py 把整帧切成 ≤50 ms 的小块，控制周期因此保持在约 50 ms，1×~100× 都稳。
    但 500×/1000× 的块长是 150 ms，控制周期跟着变粗，那两档可能开始晃。

Q5：中文字体显示为方框？
    config.load_font 按顺序尝试几个字体文件。如果都不存在，回退到 pygame
    默认字体。可以把系统里已有的中文字体路径加到 _FONT_FILES 列表最前面。

Q6：入轨判定反复切换？
    已修：判据现在是"进入 ≥180 km / 掉出 <150 km"的滞回，阈值附近不会再来回跳。
    两个阈值都在 config.py（ORBIT_MIN_PERIGEE_ALT / ORBIT_EXIT_PERIGEE_ALT）。

Q7：rocket_config.json 改了没生效？
    看控制台和 HUD 事件区第一行的"参数来源"：
      · 显示 rocket_config.json        → 改动生效了；
      · 显示"内置默认（... 不可用）"    → JSON 没读进去，控制台会打印具体级号和
        原因（缺字段、非数值、非正数都会报）。
    最常见的原因是语法错误（多余逗号、少引号）或把值写成了非数字。

Q8：为什么以前每次都"已入轨"，现在常显示"亚轨道（近地点过低）"？
    因为旧判据只要求近地点 > 100 km，而默认火箭的旧制导会把远地点抬到几千公里、
    近地点正好擦在 100 km 附近，于是被判成功——那种轨道几分钟内就会被阻力吃掉。
    判据抬高到 180 km 后，这类飞行会如实显示为亚轨道。想让默认火箭真正入轨，
    需要更好的末级制导（见 6.4）或调整火箭参数（见 9.2）。

Q9：飞完一次之后火箭停在地上不动了？
    正常。触地会关掉并锁死发动机（见本次修订第 2 条）。想重飞按 R；
    想复用还有燃料的这一级可以按 W 重新点火。

================================================================================
13. 已知限制
================================================================================

  1. 二维平面：只能模拟"向东"或"向西"飞行，没有真正的地球球面。飞到很远处
     时"向北"、"向南"无法表示。
  2. 地球自转没有被真正模拟：世界是"地面静止的惯性系"（没有科氏力/离心力），
     因此入轨速度要求比真实发射场贵约 438 m/s。为什么不能简单叠加那 438 m/s，
     见 5.5——那是本 README 里最值得读的一节。
  3. 只考虑二体引力：没有月球、太阳引力，没有 J2 摄动。
  4. 大气模型是解析式：rho = RHO0 × exp(-h/H)，真实大气随季节、纬度、太阳
     活动变化很大；而且 rho 在 200 km 处被硬截断为 0。
  5. 风廓线是解析式：没有用实测探空数据。
  6. 没有多体分离动力学：碎片只受重力和阻力，碎片之间没有相互作用。
  7. 没有燃料晃动：贮箱里燃料按均匀分布算，不模拟 slosh。
  8. 没有上面级残余推力：关机后贮箱蒸发产生的微弱推力没模拟。
  9. 姿态是单自由度：只有 pitch（theta），没有 roll 和 yaw。
 10. TVC 作动器是一阶模型：真实作动器还有非线性、死区、滞回。
 11. 没有热防护烧蚀：再入时只加热流值，箭体不会因烧蚀而减重。
 12. 末级制导只有"抬远地点 → 滑行 → 圆化"三段式，目标是固定的实例属性
     （远地点 300 km / 近地点 200 km），没有"入轨后维持/离轨"阶段，也不会
     按剩余推进剂自适应；圆化 burn 跨在远地点两侧，所以结果总是偏椭圆
     （默认配置实测 181 × 1179 km，而不是圆轨道）。
 13. Isp 只用真空值：不随环境气压变化，海平面性能高估约 10~15%（没有喷管
     面积比模型，也没有高度补偿）。
 14. 积分器混用且方向相反：dt ≤ 0.06 s 走 20 步显式欧拉，dt > 0.06 s 才走 RK4。
     于是 1×~100× 全程是低阶欧拉（慢），最粗的 RK4 反而只用在 500×/1000× 上。
     统一成 RK4 可以同时提高精度和速度（两条路径的守恒性都已由
     tools/orbit_check.py 验证，所以这是性能问题，不是正确性问题）。
 15. "自动学习"是伪学习：奖励算出来只写日志，真正改表的是四个固定乘子，
     整张 15 节点表共享一个标量（现在至少按预设分开了）；默认火箭的推进剂余量
     约 2 km/s（理想 Δv ≈11.8 km/s 对 LEO 需求的 ~9.7 km/s），飞行几乎必定成功，
     学习信号退化为"永远 +1"。
 16. 近月点预测还有偏差：TLI 关机时预测 38 万公里、实际交会 2 万公里。
     所以月球任务故意瞄准 **15,000 km 的远距交会**（瞄准误差 ±5,000 km 也只是
     "远一点/近一点"，不会撞月），再由近月制动把轨道收圆。真正的做法是加
     中段修正（MCC）用预测去闭环修正，这一步没做。
 17. 月球自身的运动是"给定"的：地心匀速圆周、共面、无摄动，也不参与动量交换。
     真实月球还有 5.1° 倾角、0.055 偏心率和太阳摄动。
 18. 验证设施仍不完整：现在有 requirements.txt 和三个无头自检脚本
     （orbit_check / moon_orbit_check / flight_test），但没有单元测试框架
     （pytest）、没有 CI，回归也只能人工对比输出——上面多数问题长期没被发现，
     根源就在这里。

这些限制都不影响"演示现代三级火箭发射过程"这个核心目标。要完全消除它们，
需要把项目升级成真正意义上的"六自由度轨道力学仿真器"，那是另一个量级的
工程。
